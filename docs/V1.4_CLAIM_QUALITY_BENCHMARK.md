# V1.4 — Claim-quality benchmark and NLI research

V1.4 is an evaluation milestone. It does **not** replace `explicit-text-v1` in production and it does not alter retrieval, AidRanker, fusion, diversity, or the V1.3 response contract.

## Goal

Establish a reviewed benchmark from real AidLens result passages before considering a learned stance classifier.

The workflow is:

1. sample claims from the existing 30-query benchmark families;
2. review the sampled claims without changing the source statement;
3. score the current `explicit-text-v1` baseline against the reviewed labels;
4. optionally compare a local zero-shot NLI model against the exact same records;
5. retain V1.3 in production unless a learned alternative wins on reviewed evidence without unacceptable precision or latency regressions.

## Label contract

Every benchmark record keeps the exact source sentence/span and receives one final `gold_stance`:

- `supports` — the sentence asserts an observed favorable program/intervention effect or directional outcome;
- `mixed` — the sentence explicitly reports mixed, heterogeneous, or conflicting observed effects;
- `contradicts` — the sentence asserts an observed null, adverse, failed, or unsustained effect;
- `insufficient` — the sentence is effect-related but does not provide enough explicit direction to support one of the three effect stances;
- `not_an_effect_claim` — the sentence is not an observed effect claim, including questions, recommendations, prospective/hypothetical statements, definitions, methods, indicator labels, or contextual descriptions.

The benchmark must not infer a causal claim merely because a passage came from a findings/results section.

## Sampling

The source query file remains:

```text
apps/api/benchmarks/queries.v1.jsonl
```

It contains six query families with five queries each. The default V1.4 sample selects the first two queries from every family, giving 12 stratified queries. Each search returns five diversified passages with a maximum of two passages per evaluation. Grounded claims are deduplicated by chunk ID and source-span offsets.

No Docker image rebuild is required to sample after checking out the branch because the API source directory is bind-mounted in development.

From the repository root:

```bash
git switch agent/v1.4-claim-quality-benchmark
git pull origin agent/v1.4-claim-quality-benchmark

docker compose exec -T api \
  python -m app.claim_eval_cli sample \
  --per-family 2 \
  --top-k 5 \
  --max-per-evaluation 2
```

The default output is:

```text
apps/api/benchmarks/claim-quality.review.local.jsonl
```

Local review and report files are gitignored.

## Review workflow

The sampler intentionally writes `gold_stance: null`. The production prediction is included for comparison, but it must not be copied automatically into the gold label.

Use the resumable terminal reviewer:

```bash
docker compose exec -T api \
  python -m app.claim_review_cli \
  benchmarks/claim-quality.review.local.jsonl
```

Labels are saved after every decision, so the review can be stopped and resumed.

For a stronger benchmark, independently double-review at least 20% of records and adjudicate disagreements before treating the file as a reference benchmark. Do not describe a single-review file as independently adjudicated.

## Baseline scoring

After review is complete:

```bash
docker compose exec -T api \
  python -m app.claim_eval_cli score-baseline \
  benchmarks/claim-quality.review.local.jsonl \
  --output benchmarks/claim-quality.explicit-text-v1.local.json
```

The report includes:

- multiclass accuracy;
- macro F1 over gold classes present in the benchmark;
- per-class precision, recall and F1;
- effect-claim detection precision/recall/F1;
- exact directional precision/recall for `supports`, `mixed`, and `contradicts`;
- directional abstention rate;
- confusion matrix;
- up to 50 disagreements for manual inspection.

`--allow-partial` exists for exploratory work, but milestone decisions must use a completely reviewed file.

## Research-only NLI comparator

The initial candidate is:

```text
MoritzLaurer/DeBERTa-v3-base-mnli-fever-anli
```

It is used only as a zero-shot research comparator. V1.4 maps five natural-language zero-shot labels to the AidLens stance contract. This is not equivalent to domain fine-tuning and must not be presented as production validation.

The NLI dependency is optional. There is no reason to rebuild/install it before the review benchmark exists. To experiment in the current development container without rebuilding the image:

```bash
docker compose exec -T api pip install '.[nli]'
```

Then run:

```bash
docker compose exec -T api \
  python -m app.claim_eval_cli compare-nli \
  benchmarks/claim-quality.review.local.jsonl \
  --output benchmarks/claim-quality.nli.local.json
```

The first run may download the model into the existing Hugging Face cache volume.

## Predeclared promotion gate

No learned stance model should replace `explicit-text-v1` unless all of the following are true on the same fully reviewed benchmark:

1. the benchmark covers all six query families;
2. source statements and provenance remain unchanged;
3. effect-claim detection precision is no worse than the deterministic baseline by more than 0.02 absolute;
4. active-class macro F1 improves by at least 0.05 absolute, or a smaller gain is accompanied by a clear and reviewed reduction in high-cost false positive effect claims;
5. precision on directional claims is not degraded in exchange for higher recall;
6. errors are reviewed by class rather than relying on aggregate accuracy;
7. inference latency and memory are measured on the deployment host;
8. the existing V1.3 deterministic extractor remains available as a fallback until the learned model has a frozen artifact, fingerprint, and reproducible packaging path.

If the reviewed benchmark contains too few gold directional claims to assess points 4–5, the correct outcome is **insufficient benchmark coverage**, not promotion.
