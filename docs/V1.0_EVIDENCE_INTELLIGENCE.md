# AidLens V1.0 — Evidence Intelligence Layer

V1.0 moves AidLens from passage retrieval toward evaluation-level development evidence intelligence while preserving the validated V0.9 ranking contract.

## Ranking contract

V1.0 does not retune retrieval or ranking:

- first stage: `BAAI/bge-base-en-v1.5` semantic retrieval
- reranker: AidRanker V1
- frozen fusion alpha: `0.50`
- validated result depth: `top_k=10`
- default evidence spread: maximum three passages per evaluation

## Product model

Search responses retain the backwards-compatible flat `hits` list and add `groups`, where each group represents one source evaluation. Group order follows the first appearance of that evaluation in the ranked hit list.

Each group exposes four product dimensions:

1. **Intervention** — the source `project_title` when available, otherwise the evaluation title. No intervention text is generated.
2. **Context** — structured archive metadata such as locations, institutions and keywords.
3. **Outcome evidence** — only passages from explicitly outcome-oriented sections are counted as outcome evidence. Findings/results/conclusions are classified as `outcome`; sustainability remains its own role but contributes to the outcome-evidence count.
4. **Evidence** — the actual ranked passages, source sections, evidence roles and retrieval/ranking scores.

The grouping layer deliberately avoids synthesizing causal claims or outcome summaries that are not present in the source corpus.

## Evidence roles

Deterministic role taxonomy:

- `outcome`: findings, results, conclusions
- `sustainability`: sustainability
- `recommendation`: recommendations
- `method`: methodology, evaluation questions
- `context`: abstract, introduction, background
- `implementation`: lessons learned
- `supporting`: any section that does not safely map to one of the roles above

`executive_summary` remains `supporting` because it commonly mixes methods, context, outcomes and recommendations.

## Ranking observability

Every search response now reports:

- `ranking_pipeline`
- `first_stage_latency_ms`
- `reranker_latency_ms`
- `total_search_latency_ms`
- `reranker_model`
- `reranker_model_fingerprint` for local model artifacts

For a local AidRanker deployment, the fingerprint is SHA-256 over the model configuration and SafeTensors weights. This lets a benchmark, production response or incident report identify the exact artifact used for ranking.

## Backwards compatibility

Existing API consumers can continue reading `hits`. The new `groups` field is additive. Lexical, semantic and hybrid diagnostic modes remain available, and AidRanker fail-open/fail-closed behavior from V0.9 is unchanged.

## Next evidence-intelligence layers

V1.0 establishes the evaluation-level contract needed for later capabilities:

- structured intervention/outcome extraction
- cross-evaluation What Works synthesis
- supporting vs contradictory evidence views
- transferability/context comparison
- evidence-strength estimation
- EvalGraph relationships between interventions, contexts, outcomes and evaluations

Those later layers should build on explicit extracted fields and provenance rather than infer unsupported claims from titles or snippets.
