# AidLens V1.3 — Grounded claims and stance

V1.3 adds a conservative claim layer on top of the frozen V1.2 retrieval,
AidRanker, diversity and cross-evaluation synthesis pipeline.

## Goal

Move from:

> these evaluations share evidence roles and context signals

toward:

> these exact returned source sentences contain explicit effect language that is
> supportive, contradictory, mixed, insufficient to classify, or not an effect
> claim.

The feature is designed for traceability first. It is not a generated narrative
summary and it is not an adjudicated causal meta-analysis.

## Frozen ranking contract

V1.3 runs only after final ranked/diversified hit selection. It does not modify:

- BGE first-stage retrieval;
- AidRanker V1 weights;
- Torch serving backend;
- AidRanker batch size 8;
- candidate pool 40;
- fusion alpha 0.50;
- top-k 10;
- default max 3 passages per evaluation.

The V1.2 `hits`, `groups`, recurring facets and context-overlap behavior remain
additive-compatible.

## Claim extractor

The production baseline is identified as:

```text
explicit-text-v1
```

It uses deterministic sentence-span extraction and conservative explicit-text
patterns. The extractor never rewrites the source sentence.

Each grounded assessment contains:

- evaluation ID;
- source chunk ID;
- section and evidence role;
- exact source sentence;
- start/end character offsets inside the returned passage;
- stance;
- conservative signal confidence;
- exact matched textual basis;
- explicit conditional phrase when one is present;
- source URL.

The source-span invariant is:

```python
hit.text[claim.source_span_start:claim.source_span_end] == claim.statement
```

## Stance states

### `supports`

The sentence contains explicit supportive effect language, such as a reported
improvement, effectiveness, achieved target, contribution, or clearly specified
beneficial change.

### `contradicts`

The sentence contains explicit negative/no-effect language, such as no significant
effect, failed to improve, ineffective, or no evidence of benefit.

### `mixed`

The sentence explicitly reports mixed/inconsistent/heterogeneous results or contains
both supportive and contradictory effect signals.

### `insufficient`

The sentence discusses an effect, impact or outcome but does not provide enough
explicit direction to assign a stronger stance.

### `not_an_effect_claim`

No explicit effect signal is present in the selected source sentence. This is an
intentional abstention state, not a negative judgment.

## Critical constraint

Section labels and metadata never determine stance.

For example, a passage tagged `findings` can still be classified as
`not_an_effect_claim` if its actual text contains no effect statement. Conversely,
a methodology passage can receive a stance only if its own sentence explicitly
contains effect language.

## Conditions

V1.3 surfaces limited explicit conditional phrases introduced by textual markers
such as `when`, `where`, `if`, `provided that`, `only when`, `only where`, or
`among`.

These are source-text fragments, not generated transferability conclusions.

## Cross-evaluation output

The existing `synthesis` object now additionally exposes:

- `claim_extractor`;
- `claims`;
- `stance_coverage`;
- `effect_claim_evaluation_count`.

`stance_coverage` reports both distinct evaluation count and claim count for each
stance.

## UI

The cross-evaluation evidence map now includes:

1. effect-claim evaluation count;
2. stance distribution;
3. a grounded claim register;
4. exact source sentences;
5. confidence and matched textual basis;
6. explicit conditions;
7. direct source links;
8. the existing evidence coverage, recurring themes and context-overlap views.

## What V1.3 does not claim

V1.3 does not:

- estimate causal effect size;
- decide whether an evaluation design is internally valid;
- infer contradiction from section labels or metadata;
- infer that one context will transfer to another;
- turn `supports` into a universal `works` verdict;
- generate missing claims when the source passage is ambiguous;
- replace expert evidence synthesis.

The signal confidence is confidence in the explicit lexical stance signal, not a
probability that the intervention truly caused the reported outcome.

## Validation gates

CI:

- API install passes;
- Ruff passes;
- API tests pass;
- Next.js production build passes.

Live corpus/model smoke:

1. V1.2/V1.1 ranked top-10 chunk order remains unchanged;
2. every claim source span reproduces the exact source substring;
3. every claim references one returned hit/evaluation;
4. stance coverage sums to the number of claim assessments;
5. every `supports`, `mixed`, `contradicts` or `insufficient` claim has textual
   stance basis;
6. `not_an_effect_claim` is allowed and expected;
7. the live response identifies `claim_extractor=explicit-text-v1`;
8. the existing synthesis counts and context-overlap invariants still pass.

## Next research step

A learned local NLI/stance model should be considered only after V1.3 establishes a
reviewed claim/stance validation set from real AidLens passages. The deterministic
baseline provides an auditable comparison point and candidate examples for that
future evaluation.
