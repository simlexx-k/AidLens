# AidLens V1.1 — Serving Performance

V1.1 improves production search latency without retuning the validated ranking contract.

## Frozen ranking contract

The following remain unchanged from V0.8–V1.0:

- first stage: `BAAI/bge-base-en-v1.5`
- reranker: AidRanker V1
- fusion alpha: `0.50`
- production candidate pool: `40`
- production `top_k`: `10`
- default diversity limit: max 3 passages per evaluation
- production reranker backend: Torch

V1.1 does not change relevance judgments, training data, model weights, candidate count, or fusion coefficients.

## Measurement correction

The original V1.0 smoke measurement mixed lazy model construction into the first reranker request, while query embedding occurred outside `total_search_latency_ms`.

V1.1 therefore adds:

- process-local semantic encoder and AidRanker instances
- startup model warmup
- query-encoding latency
- first-stage retrieval latency
- reranker inference latency
- internal-search latency
- end-to-end request latency
- repeatable serving benchmarks

## Warm Torch baseline — batch 32

Seven production-path requests were measured after startup warmup using the frozen 40-candidate pool.

Median:

- client wall: `3048.134 ms`
- end-to-end request: `3044.851 ms`
- query encoding: `156.004 ms`
- semantic retrieval: `26.094 ms`
- AidRanker: `2508.859 ms`
- internal search: `2824.393 ms`

P95:

- request: `3379.359 ms`
- AidRanker: `2846.834 ms`

One-time AidRanker model load: `634.989 ms`.

Conclusion: cold start was not the dominant bottleneck. Warm AidRanker inference consumed roughly 82% of median request latency.

## Torch batch-size sweep

The same 40 semantic candidates were reranked with batch sizes 8, 16, 32 and 40. All variants preserved the exact final fused + diversity-capped top-10 chunk order.

| Batch | Median reranker | Max raw-score delta vs 32 | Top-10 parity |
| ---: | ---: | ---: | --- |
| 8 | `1840.804 ms` | `4.768e-7` | exact |
| 16 | `1867.568 ms` | `2.384e-7` | exact |
| 32 | `2022.576 ms` | `0` | exact |
| 40 | `2112.312 ms` | `2.533e-6` | exact |

Batch 8 was selected.

## Production-path batch-8 validation

Seven production-path requests with batch 8 produced:

Median:

- client wall: `2216.204 ms`
- end-to-end request: `2212.760 ms`
- query encoding: `103.948 ms`
- semantic retrieval: `17.861 ms`
- AidRanker: `1898.105 ms`
- internal search: `2093.219 ms`

P95:

- request: `2491.018 ms`
- AidRanker: `2366.385 ms`

One-time AidRanker model load: `562.302 ms`.

Compared with batch 32, median end-to-end request latency improved by about 27%, while median reranker latency improved by about 24%. The ranking contract remained unchanged.

**V1.1 production default: Torch + batch size 8.**

## Accelerated-runtime experiment

Torch, ONNX and OpenVINO were benchmarked on the exact same 40 candidates, using batch 8 and the same frozen fusion/diversity logic.

| Backend | Median reranker | Max raw-score delta vs Torch | Top-10 parity |
| --- | ---: | ---: | --- |
| Torch | `1862.814 ms` | `0` | exact |
| ONNX | `1861.889 ms` | `6.914e-6` | exact |
| OpenVINO | `1691.356 ms` | `4.530e-6` | exact |

Observed model-load/export times:

- Torch: `557.267 ms`
- ONNX: `3676.715 ms`
- OpenVINO: `6862.601 ms`

ONNX provides no meaningful steady-state improvement over Torch on this host. OpenVINO improves median reranker inference by roughly 9%, but the absolute gain is only about 171 ms and introduces another runtime/export artifact into production.

Decision: keep Torch in production for V1.1. Retain ONNX/OpenVINO as benchmarkable optional runtimes rather than shipping a backend switch for a marginal gain.

## Runtime configuration

```env
AIDLENS_API_EXTRAS=ml
AIDLENS_EMBEDDING_PROVIDER=sentence-transformers
AIDLENS_AIDRANKER_PROVIDER=sentence-transformers
AIDLENS_AIDRANKER_MODEL=models/aidranker-v1.local
AIDLENS_AIDRANKER_CANDIDATE_K=40
AIDLENS_AIDRANKER_BATCH_SIZE=8
AIDLENS_AIDRANKER_DEVICE=auto
AIDLENS_AIDRANKER_WARMUP=true
AIDLENS_AIDRANKER_FAIL_OPEN=true
```

Optional experiment-only extras remain available:

```bash
pip install -e './apps/api[ml,onnx]'
pip install -e './apps/api[ml,openvino]'
```

They are not required for the V1.1 production Torch deployment.

## Version provenance caveat

During the accelerated-runtime experiment, the model artifact reported that it had been created with Sentence Transformers `6.0.0`, while the benchmark container reported Sentence Transformers `5.7.0`. Inference completed successfully, backend score deltas were very small, and final top-10 parity was exact, but the mismatch should be treated as a reproducibility warning.

Do not force a package upgrade solely to silence the warning. A future model-packaging milestone should record the exact training/export environment and regenerate the deployment artifact under a reproducible released dependency set.

## V1.1 decision

Ship:

- startup warmup
- shared process-local ML services
- corrected end-to-end latency telemetry
- serving benchmark tooling
- Torch batch size 8
- optional ONNX/OpenVINO experiment dependencies

Do not ship:

- a candidate-pool reduction
- a fusion-alpha change
- an ONNX backend switch
- an OpenVINO backend switch

The next performance work should target model/runtime architecture only if product latency requirements demand substantially less than the current ~2.2 s median end-to-end response. A future candidate-pool reduction requires separate ranking-quality evidence rather than serving-only timing evidence.
