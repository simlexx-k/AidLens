# AidLens V1.1 — Serving Performance

V1.1 optimizes serving latency without retuning the validated ranking contract.

## Frozen ranking contract

The following remain unchanged from V0.8–V1.0:

- first stage: `BAAI/bge-base-en-v1.5`
- reranker: AidRanker V1
- fusion alpha: `0.50`
- production `top_k`: `10`
- default diversity limit: max 3 passages per evaluation
- Torch remains the production CrossEncoder backend in the first V1.1 pass

V1.1 must not change relevance judgments, training data, model weights, or fusion coefficients.

## Why the V1.0 latency sample needs a new baseline

The V1.0 live smoke test reported:

- semantic first stage: 571.431 ms
- AidRanker stage: 2611.017 ms
- internal search total: 3537.886 ms

Two cold-start effects were mixed into that single request:

1. `SentenceTransformerEncoder` was process-lazy and could load BGE on the first semantic request.
2. `AidRankerService._model` was a cached property, so the first rerank included CrossEncoder construction and weight loading.

Also, `total_search_latency_ms` started after query embedding, so it was not an end-to-end request measurement.

## V1.1 phase 1

V1.1 first removes measurement ambiguity before considering backend changes:

- one process-local semantic encoder singleton
- one process-local AidRanker singleton
- startup warmup for the semantic encoder
- startup AidRanker warmup when enabled
- configurable Torch batch size and device
- explicit query-encoding latency
- first-stage retrieval latency
- AidRanker inference latency
- internal search latency
- end-to-end route latency
- repeatable live benchmark command with median and p95 summaries

The default AidRanker batch remains 32 and the default device remains automatic selection, preserving existing behavior.

## Runtime configuration

```env
AIDLENS_API_EXTRAS=ml
AIDLENS_EMBEDDING_PROVIDER=sentence-transformers
AIDLENS_AIDRANKER_PROVIDER=sentence-transformers
AIDLENS_AIDRANKER_MODEL=models/aidranker-v1.local
AIDLENS_AIDRANKER_CANDIDATE_K=40
AIDLENS_AIDRANKER_BATCH_SIZE=32
AIDLENS_AIDRANKER_DEVICE=auto
AIDLENS_AIDRANKER_WARMUP=true
AIDLENS_AIDRANKER_FAIL_OPEN=true
```

## Live benchmark

After rebuilding/restarting the API, run:

```bash
docker compose exec api \
  python -m app.ranker_cli benchmark-serving \
  --repeats 7 \
  --output benchmarks/aidranker-v1-serving.local.json
```

The report includes per-run and summary values for:

- client wall latency
- query embedding latency
- first-stage retrieval latency
- reranker latency
- internal search latency
- end-to-end route latency
- one-time model load latency
- serving batch size and device

Use warm-run medians and p95 values for performance decisions rather than a single first request.

## Optimization order

1. Establish warm Torch baseline after startup warmup.
2. Test batch sizes using the same query set and model artifact.
3. Profile candidate-pool cost without changing the production value of 40 until ranking parity is demonstrated.
4. Only then evaluate SentenceTransformers-supported ONNX or OpenVINO CrossEncoder backends.
5. A backend or candidate-pool change can ship only after output/ranking parity is checked against the frozen Torch configuration.

SentenceTransformers supports Torch, ONNX, and OpenVINO CrossEncoder inference. ONNX/OpenVINO remain experimental for AidLens until local performance and ranking-parity evidence justify a production switch.
